# 项目管理（Project Manager）实施规划

> 目标：在现有会话管理旁边增加“项目管理”。项目由会话实际使用的文件夹（`projectDir` / Codex `cwd`）代表；项目可为指定客户端绑定上游供应商。没有绑定的项目继续使用全局默认供应商，绑定项目的请求在代理路由阶段优先使用指定供应商，不修改全局供应商。

## 1. 用户流程

1. 用户打开“项目管理”。
2. CC Switch 扫描现有 Claude/Codex 等会话，按标准化后的 `projectDir` 合并为项目。
3. 项目卡片展示目录、会话数量、最近活跃时间、涉及的客户端和当前项目渠道。
4. 用户为项目选择客户端和上游供应商，或恢复为“跟随全局”。
5. Codex 请求进入本地代理后：
   - 从 `session_id` / `x-session-id` 提取稳定会话 ID；
   - 通过本地会话元数据把 session ID 映射到 `cwd`；
   - 标准化目录并查找项目级供应商覆盖；
   - 有覆盖时优先使用指定供应商，无覆盖时沿用现有默认路由。
6. 项目级路由只影响该项目请求，不改变全局当前供应商。

## 2. 路由优先级

```text
项目级指定供应商 > 全局当前供应商 > 现有故障转移/默认逻辑
```

初版项目覆盖采用“指定供应商单路由”语义：指定供应商不可用时返回错误，不静默回退到全局供应商，避免实际渠道与用户配置不一致。后续可增加项目级备用供应商。

## 3. 数据模型

新增 `project_provider_routes` 表：

- `project_path_key`：标准化路径，主键的一部分；
- `project_path`：用于展示的原始/最近路径；
- `app_type`：`codex`、`claude` 等客户端；
- `provider_id`：供应商卡片 ID；
- `enabled`、`updated_at`。

会话本身仍然扫描本地文件，不复制 transcript 到数据库。项目是会话目录的运行时聚合，数据库只持久化用户主动设置的渠道覆盖。

## 4. 首期范围

- 增加与会话管理并列的“项目管理”页面入口；
- 按文件夹合并现有会话；
- 项目搜索、刷新、展开会话；
- 配置/清除项目级供应商；
- 接入代理路由：Codex 优先按项目供应商转发；
- 供应商被删除或路径不可解析时安全回退到全局路由，并在 UI 显示状态；
- 新增 Rust/前端单元测试覆盖路径规范化、项目分组、项目路由优先级。

## 5. 兼容和边界

- `request_id` 是单次请求 ID，不能用于项目识别；使用稳定的 Codex session ID。
- 首条请求尚未建立 session -> cwd 映射时，继续走全局默认供应商；映射建立后后续请求走项目路由。
- session 映射以 `app_type + session_id` 为 key，避免不同客户端 ID 碰撞。
- 官方 Codex 账号的原生认证边界保持现有安全规则；项目覆盖仅作用于代理可控的供应商。
- 项目路径不作为 shell 命令拼接内容，继续由现有终端启动器负责安全转义。

## 6. 实施步骤

### M1：数据和项目视图

- 数据库表和 DAO；
- Tauri 项目命令；
- 前端项目页面；
- 按目录合并会话并展示渠道。

### M2：代理项目路由

- session ID -> Codex cwd 索引；
- ProviderRouter 增加指定 provider 选择；
- RequestContext 解析项目覆盖；
- 请求日志保留实际 provider 归因。

### M3：测试和体验

- 迁移、DAO、路径、路由测试；
- 供应商删除/目录不存在/首请求未知场景；
- 多项目并发验证；
- 中英文 i18n 文案补齐。

## 7. 验收标准

- 同一文件夹下不同渠道的会话展示在同一个项目下；
- 设置项目渠道后，只有该项目请求使用指定供应商；
- 其他项目和未配置项目仍按全局供应商工作；
- 不需要通过切换全局供应商来实现项目路由；
- 删除项目绑定只删除覆盖关系，不删除会话文件和供应商；
- 路径、会话 ID、供应商 ID 缺失时不崩溃，有可解释的降级行为。
