# 项目管理（Project Manager）实施规划

> 目标：在现有会话管理旁边增加“项目管理”。项目由会话实际使用的文件夹（`projectDir` / Codex `cwd`）代表；项目可为指定客户端绑定上游供应商。没有绑定的项目继续使用全局默认供应商，绑定项目的请求在代理路由阶段优先使用指定供应商，不修改全局供应商。

## 1. 用户流程

1. 用户打开“项目管理”。
2. CC Switch 扫描现有 Claude/Codex 等会话，按标准化后的 `projectDir` 合并为项目。
3. 项目卡片展示目录、会话数量、最近活跃时间、涉及的客户端、最近模型和当前项目渠道。
4. 用户为项目选择客户端和上游供应商，或恢复为“默认供应商”。
5. 用户可以为项目选择“强制路由模型”，模型列表支持输入搜索过滤和按需新增。
6. Codex 请求进入本地代理后：
   - 从 `session_id` / `x-session-id` 提取稳定会话 ID；
   - 通过本地会话元数据把 session ID 映射到 `cwd`；
   - 标准化目录并查找项目级供应商覆盖；
   - 有覆盖时优先使用指定供应商，无覆盖时沿用现有默认路由；
   - 项目开启强制模型时，在该供应商的模型映射和请求转换完成后，把最终出站 `model` 改写为指定模型。
7. 项目级路由和强制模型只影响该项目请求，不改变全局当前供应商。

## 2. 路由优先级

```text
项目级指定供应商 > 全局当前供应商 > 现有故障转移/默认逻辑

项目强制路由模型 > 客户端请求模型 > 供应商默认模型映射
```

项目覆盖采用“指定供应商单路由”语义：指定供应商不可用时返回错误，不静默回退到全局供应商，避免实际渠道与用户配置不一致。后续可增加项目级备用供应商。

强制模型是最终出站值的权威覆盖，优先级高于客户端模型、供应商模型映射、Codex Responses 到 Chat/Anthropic 的兼容转换以及供应商自定义 request overrides。它不会改变全局供应商模型配置。

## 3. 数据模型

新增 `project_provider_routes` 表：

- `project_path_key`：标准化路径，主键的一部分；
- `project_path`：用于展示的原始/最近路径；
- `app_type`：`codex`、`claude` 等客户端；
- `provider_id`：供应商卡片 ID；
- `enabled`：项目供应商路由是否启用；
- `force_model_enabled`：项目强制路由模型开关，数据库默认值为 `0`；
- `force_model`：项目强制使用的最终出站模型名，可为空；
- `updated_at`：最近更新时间。

全局强制模型候选列表存放在 `settings.project_force_model_options`，以 JSON 字符串数组保存。该列表被所有项目、Codex 和 Claude 共用；新增会自动去重，删除只影响候选列表。

会话本身仍然扫描本地文件，不复制 transcript 到数据库。项目是会话目录的运行时聚合，数据库只持久化用户主动设置的渠道覆盖和强制模型配置。

## 4. 项目管理界面

- “项目管理”与会话管理并列；
- 顶部使用和首页一致的项目类型切换（Codex / Claude Code）；
- 下方是项目列表，项目卡片展示目录、最近模型和供应商选择；
- 供应商选择使用与模型选择一致的紧凑搜索下拉框，只支持选择供应商或恢复默认供应商，不提供新增和删除；
- 供应商选择框后直接显示模型下拉框，不再显示“强制路由模型”文字标签；
- 未输入时，当前选中模型或关闭状态作为灰色占位提示显示，输入搜索内容后直接过滤模型；
- 下拉框第一项固定为“关闭强制路由模型”，选中任意模型会立即开启强制路由；
- 仅当搜索内容非空且没有匹配模型时，显示“新增‘输入内容’”按钮；点击后按输入内容新增、选中并开启；
- 已有候选项可从列表内删除，列表底部不保留固定的“新增模型”按钮；
- 新项目默认关闭强制模型；
- 未选择项目供应商时不能开启强制模型；
- 全局候选中已删除但仍被项目使用的模型继续保留在项目配置中，并标记“已移除”，避免运行中的项目被静默切换到其他模型；
- 清除项目供应商会删除整条项目路由，包括强制模型配置。

## 5. 首期范围

- 增加与会话管理并列的“项目管理”页面入口；
- 按文件夹合并现有会话；
- 项目搜索、刷新、展开会话；
- 配置/清除项目级供应商；
- 增加全局强制模型候选列表的新增、选择和删除；
- 配置项目级强制路由模型（默认关闭）；
- 接入代理路由：Codex 优先按项目供应商转发，并在最终出站前强制模型；
- 供应商被删除或路径不可解析时安全回退到全局路由，并在 UI 显示状态；
- 新增 Rust/前端单元测试覆盖路径规范化、项目分组、项目路由优先级和强制模型覆盖。

## 6. 兼容和边界

- `request_id` 是单次请求 ID，不能用于项目识别；使用稳定的 Codex session ID。
- 首条请求尚未建立 session -> cwd 映射时，继续走全局默认供应商；映射建立后后续请求走项目路由。
- session 映射以 `app_type + session_id` 为 key，避免不同客户端 ID 碰撞。
- 官方 Codex 账号的原生认证边界保持现有安全规则；项目覆盖仅作用于代理可控的供应商。
- 项目路径不作为 shell 命令拼接内容，继续由现有终端启动器负责安全转义。
- 强制模型名称去首尾空白，长度上限 200，禁止换行。
- 强制模型只在项目级供应商路由存在且开关开启时生效，避免“配置了模型但实际没有项目路由”的歧义。

## 7. 实施步骤

### M1：数据和项目视图

- 数据库表和 DAO；
- Tauri 项目命令；
- 前端项目页面；
- 按目录合并会话并展示渠道。

### M2：代理项目路由

- session ID -> Codex cwd 索引；
- ProviderRouter 增加指定 provider 选择；
- RequestContext 解析项目覆盖；
- 请求日志保留实际 provider 归因；
- 最终出站 JSON 强制模型覆盖。

### M3：测试和体验

- 迁移、DAO、路径、路由测试；
- 供应商删除/目录不存在/首请求未知场景；
- 多项目并发验证；
- Codex/Claude 界面文案补齐。

## 8. 验收标准

- 同一文件夹下不同渠道的会话展示在同一个项目下；
- 设置项目渠道后，只有该项目请求使用指定供应商；
- 其他项目和未配置项目仍按全局供应商工作；
- 项目开启强制模型后，最终出站请求使用指定模型，不受客户端模型和供应商映射影响；
- 项目默认关闭强制模型，关闭时请求行为与未配置该功能一致；
- 全局模型候选列表可新增、去重、删除；
- 删除项目绑定只删除覆盖关系，不删除会话文件和供应商；
- 路径、会话 ID、供应商 ID 缺失时不崩溃，有可解释的降级行为。
